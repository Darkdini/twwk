# Разбор рукопожатия и логина (реальный дамп регистрации)

Источник: `twwk_dump_*.bin` / `twwk_msg_*.txt` (захват с устройства Xiaomi,
клиент 2.0.112). Тестовые учётки — не настоящие.

## Транспортное рукопожатие (подтверждено)
```
C -> S:  38 0F                  (HELLO)
S -> C:  38 0F                  -> server_version=56, flags=15
```
Совпадает с реверсом из APK (`h/C0274b.c()`).

## Кадрирование
Все прикладные сообщения идут транспортным `type=0`, кадр `[0][varint len][payload]`.
Маршрутизация — ВНУТРИ payload: `[srcId:int32][opcode:int32][body]`, где
`srcId`/`opcode` — хеши имён (см. `twwk/opcodes.py`). По сути это remote-UI:
«объекту srcId установить свойство opcode = тело».

**Строки кодируются UTF-16BE** (версия 56 > 27 ⇒ `writeChars`), длина —
varint в символах.

## Последовательность логина/регистрации (хронология)
| № | Напр. | Что |
|---|------|-----|
| 1 | C→S | `Android \| Client version 2.0.112` + `Xiaomi \| 2306EPN60G \| 15` + null,null (девайс/версия) |
| 2 | S→C | список хостов `socket://mmog…:5005\|…:5005` + первичная настройка |
| 3 | C→S | подтверждения/запросы |
| 4 | C→S | **рег/логин**: `<login> \| <pass> \| none \| {"instid":"PDA_LIFE","brand":…,"uid":…}` |
| 5 | S→C | `!LoadMap`, `!background`, экран **«Логин / Ваш…»** (UI логин-формы) |
| 6 | C→S | submit `<login> \| <pass>` |
| 7 | S→C | экран «Забыли пароль», форма `Логин / Пароль / Выберите су:` |
| 8 | C→S | регистрация нового: `<nick> \| <login> \| <pass>` |
| 9 | S→C | эхо принятого аккаунта: `<login>`, `<pass>`, директива `@GT1.FORM(-1)` |
| 10 | C→S | FCM push-токен (`…:APA91b…`) |
| 11 | S→C | главный экран: `LinkScr … Профиль …` (≈7 КБ), здания, «Добро пожаловать» |

## Поля пакета девайс/логина (C→S, type=0)
Наблюдаемые строковые поля по порядку: версия-строка, девайс-строка,
2× служебные, **login**, **password**, `none`, JSON c `instid/brand/model/uid`.
Точный байт-лейаут (заголовок перед строками) — доразобрать по билдеру пакета
в клиенте; строки — `[varint charCount][UTF-16BE]`.

## Тела сообщений (классы из APK)
`i.g` (1640), `null` (1329 — чистая команда без тела), `k.e` (639),
`w.d` (223), `r.c`, `r.d`, `u.d`, `x.b`, `k.h`, `j.d`, `k.b`, `i.b`, `u.c`.
Это типы значений свойств (число/строка/изображение/виджет и т.п.) —
следующий шаг расшифровки.

## Часто используемые опкоды в сессии
- `op`: `value` (686), `CLOSE` (549), `HIST0` (152), `ADDDIL` (143),
  `RELOAD` (116), `RELOD` (101), `add`, `delAll`, `PGSET` — это UI-операции
  (установка значения, закрытие окна, история, добавление строк, перезагрузка).
- `srcId`: `_VIS`, `_THIS`, `_MOS`, `MEMQ`, `MEM` + множество хешей имён
  конкретных виджетов.
