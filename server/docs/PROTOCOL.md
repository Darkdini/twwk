# Протокол TWWK — спецификация (из реверса клиента 2.0.112)

Все ссылки — на классы из `jadx`-декомпиляции APK.

## 1. Соединение (`J/b.java`, `J/a.java`)

- `assets/conect.conf`: `Gsocket://mmog1.com:5005|socket://mmog2.com:5005`
  (разделитель `|`, два сервера для failover; ведущий байт `G` — служебный).
- `J.b.h(String)` парсит `socket://host:port`: `indexOf(":", 9)` (после
  `socket://`), host = `substring(9, idx)`, port = остаток.
- Открывается `new Socket(addr, port)`, `setTcpNoDelay(true)`.
- Входной поток оборачивается в `DataInputStream`, выходной — в
  `DataOutputStream`. TLS/шифрования нет.

## 2. Рукопожатие (`h/C0274b.java: c()` / `b()`)

```
C -> S:  0x38 0x0F            // new byte[]{56, 15}, затем flush()
S -> C:  serverVer  flags     // 2 байта (поля f3555b, f3556c)
```
- `e()` = `min(serverVer, 56)` — версия протокола для записи (cap = 56).
- `g()` = `flags <= 56`.
- Состояние `f3554a` идёт 0→3; при `3` соединение готово.

## 3. Чтение сообщений (`h/C0274b.java: a()`, `h/AbstractC0273a.java: f()`)

Цикл:
1. читается 1 байт `type` (`f3561h`); валиден диапазон `[0, adapters.length)`;
2. `adapters[type].f(in)` читает тело: `len = varint`, затем `len` байт payload;
3. payload разбирается конкретным адаптером (`a(byte[], C0610b)`).

Итоговый кадр: `[type:1][len:varint][payload]`.

## 4. Отправка сообщений (`h/C0274b.java: i()`, `y/C0611c.java`)

Простой путь (версия < 17): `[type][len:varint][payload]`.

Версия ≥ 17: добавляется ведущий `0`-байт (`g(false)` → `writeBoolean`),
далее опциональный префикс и payload; длина = `payloadLen + 1`.

Версия ≥ 26 (`C0611c.a()`): словарь ресурсов (шрифты/фоны) сериализуется
отдельно и предваряется 4-байтовой big-endian длиной; при пустом словаре
пишется `00 00 00 00`. Это касается батч-сообщений с ресурсами, не каждого
кадра.

Keepalive: при простое > 180000 мс клиент шлёт одиночный `0xFF`.

## 5. Varint (`y/AbstractC0612d.b()` чтение, `y/C0611c.d()` запись)

Запись `d(value)`:
| условие | байты |
|---|---|
| `value < 0` | `127`, затем `int32(value)` |
| `value < 250` | `1` байт: `value - 128` |
| `value < 65536` | `126`, затем `int16(value - 32768)` |
| иначе | `127`, затем `int32(value)` |

Чтение `b()`:
| первый байт | результат |
|---|---|
| `126` | `int16 + 32768` |
| `127` | `int32` |
| иначе | `byte + 128` |

## 6. Примитивы (`y/C0611c.java`)

- `h(int)` → 1 байт; `k(int)` → `int16`; `j(int)` → `int32`;
  `i(float)` → `float`; `g(bool)` → 1 байт; `f(byte[])` → сырые байты.
- Ссылки на ресурсы: шрифты (`AbstractC0343a`) и фоны (`AbstractC0231a`)
  пишутся как индексы в словарь (1-based, 0 = null).

## 7. Строки

### Запись (`C0611c.e()`), версия ≤ 27
`d(length)`, затем по символу в однобайтовую кодировку:
- `'А'..'я'` (1040..1103) → `char - 848`;
- спец-символы (Ё, Є, ё, є, І, Ї, і, ї, Ґ, ґ) → фикс. байты
  (`Ё→168, ё→184, …`).

Версия > 27: `writeChars(str)` — UTF-16 BE по 2 байта на символ.

### Чтение (`AbstractC0612d.a()`)
Обратная карта: `192..255 → char + 848`; спец-байты → кириллические
кодпоинты (`168→Ё`, `184→ё`, `178→І`, `179→і`, `180→ґ`, `165→Ґ`,
`170→Є`, `186→є`, `175→Ї`, `191→ї`, `166→…`).

Реализация карт — в `twwk/proto.py`.

## 8. Типы сообщений (адаптеры)

Массив `adapters: InterfaceC0275c[]` задаётся при создании `C0274b`; индекс =
`type`-байт. Конкретные реализации (`AbstractC0273a`-наследники) разбросаны по
пакетам `q/`, `i/`, `M/a.java` и др. — каждый разбирает свой payload. Точное
соответствие «type → смысл» восстанавливается по записям прокси (раздел 2
README) и дальнейшим разбором тел `a(byte[], C0610b)`.
