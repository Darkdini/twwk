# Запуск нашего сервера на телефоне (Termux) + клиент на localhost

Клиент `twwk-2.0.112-localhost.apk` ходит на `127.0.0.1:5005` (правлен
`conect.conf`). Сервер поднимаем тут же, в Termux. Логгер в клиенте оставлен —
можно писать новые дампы параллельно.

## 1. Termux
Поставь Termux (F-Droid) и в нём:
```bash
pkg update -y && pkg install -y python git
git clone https://github.com/Darkdini/twwk
cd twwk
git checkout claude/client-handshake-recording-Ax86r
```

## 2. Запустить сервер (режим login)
Готовая сессия уже лежит в репо (`server/replay_session/s2c.bin`),
конвертировать дамп НЕ нужно:
```bash
cd server
python3 server.py login --session replay_session --listen 127.0.0.1:5005
```
Должно написать `S->C=11766230 байт` (не 0!). Если 0 — значит не сделал
`git pull` свежей ветки.

> Хочешь сделать сессию из своего нового дампа — тогда:
> ```bash
> termux-setup-storage
> python3 tools/import_dump.py <путь к одному twwk_dump_XXXX.bin> -o captures/my
> python3 server.py login --session captures/my --listen 127.0.0.1:5005
> ```
> Указывай ОДИН конкретный файл (не маску `*.bin`).
Сервер ответит на рукопожатие и проиграет записанный экран логина, а в консоли
будет видно, что шлёт клиент (`<- C ... op=value «...»`).

## 4. Запустить клиент
Установи `twwk-2.0.112-localhost.apk` (удалив прежнюю версию) и открой игру.
Он подключится к `127.0.0.1:5005` (нашему серверу) и должен дойти до экрана
логина по записи.

## Заметки
- Termux должен оставаться запущенным (сервер — на переднем плане). Можно
  держать в отдельной сессии Termux.
- Это реплей записи: сервер пока «проигрывает» прошлый сеанс, не реагируя на
  каждый запрос. Цель шага — увидеть, что клиент оживает до логина. Дальше
  переходим к настоящим ответам в режиме `serve`.
- Если клиент сразу уходит на реальный сервер — проверь, что стоит именно
  `*-localhost.apk` (в `conect.conf` должно быть `127.0.0.1:5005`).
