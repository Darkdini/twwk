# TWWK сервер — инструментарий

Набор для разбора клиента **Third World War of Kings 3D 2.0.112** и написания
своего сервера: записывающий прокси (MITM), офлайн-декодер записей и заготовка
самого сервера (replay + каркас).

## Что выяснено о клиенте

| Параметр | Значение |
|---|---|
| Транспорт | сырой TCP, `setTcpNoDelay(true)` |
| Порт | **5005** |
| Серверы | `mmog1.com`, `mmog2.com` (failover), конфиг в `assets/conect.conf` |
| Шифрование | **нет** (открытый бинарный протокол) |
| Сайт | http://twwk.ru |

Источники в декомпиляции клиента: `J/b.java` (соединение), `J/a.java`
(handshake-поток), `h/C0274b.java` (рукопожатие + цикл чтения),
`h/AbstractC0273a.java` (чтение кадра), `y/AbstractC0612d.java` и
`y/C0611c.java` (varint/строки).

### Рукопожатие
```
C -> S:  38 0F                 (2 байта: 56, 15)
S -> C:  <serverVer> <flags>   (2 байта)
рабочая версия = min(serverVer, 56)
```

### Кадр сообщения
```
[type:1][len:varint][payload: len байт]
```
Тип-байт выбирает адаптер-обработчик; каждый адаптер парсит своё тело.
`0xFF` от клиента при простое >180 c — keepalive.

### Varint
- маркер `126` → дальше `int16`, значение = `short + 32768`
- маркер `127` → дальше `int32`
- иначе значение = `byte + 128`

### Строки
При версии ≤ 27 — кастомная однобайтовая кодовая страница кириллицы
(см. `twwk/proto.py: decode_legacy_string`). При версии > 27 — UTF-16
(`writeChars`).

Подробнее: [`docs/PROTOCOL.md`](docs/PROTOCOL.md).

## Состав

```
server/
  twwk/proto.py          кодек: varint, строки, кадрирование
  proxy/record_proxy.py  записывающий прокси (MITM)
  tools/decode_capture.py офлайн-разбор записей
  tools/selftest.py      тесты кодека и прокси
  server.py              наш сервер: replay записанной сессии / каркас live
  captures/              сюда пишутся сессии
```

## 1. Запись рукопожатий и трафика

Запустить прокси (на VPS или ПК, куда смотрит клиент):

```bash
cd server
python3 proxy/record_proxy.py --listen 0.0.0.0:5005 --upstream mmog1.com:5005
```

Каждое подключение пишется в `captures/<timestamp-NNNN>/`:
- `c2s.bin`, `s2c.bin` — сырые байты по направлениям (для точного replay);
- `events.jsonl` — структурный лог: chunk'и, рукопожатие, кадры, keepalive,
  с таймингами (`t_ms`).

### Как направить клиент на прокси
**Вариант A — подмена конфига (рекомендуется).** Распаковать APK, заменить
`assets/conect.conf`:
```
Gsocket://<IP_прокси>:5005|socket://<IP_прокси>:5005
```
(первый байт `G` оставить как в оригинале), пересобрать `apktool b` и
переподписать `apksigner`. Прокси ходит на настоящий `mmog1.com:5005`.

**Вариант B — DNS/hosts.** На устройстве (root/эмулятор) указать
`mmog1.com → IP прокси`; прокси запускать с `--upstream <реальный IP>:5005`.

## 2. Разбор записи

```bash
python3 tools/decode_capture.py captures/<session>/events.jsonl
# или сырой дамп:
python3 tools/decode_capture.py --raw captures/<session>/s2c.bin --dir s2c
```

## 3. Воспроизведение на нашем сервере

```bash
# проиграть записанную сессию реальному клиенту (тайминги опционально):
python3 server.py replay --session captures/<session> --listen 0.0.0.0:5005 --realtime
```
Сервер отвечает на `38 0F` записанными байтами версии и проигрывает все
кадры S→C, логируя кадры клиента. Это проверка, что клиент «оживает».

Каркас живого сервера (диспетчер по типам сообщений — заполнять по мере
разбора кадров):
```bash
python3 server.py serve --listen 0.0.0.0:5005 --version 56 --flags 0
```
Обработчики добавляются декоратором `@handler(<type>)` в `server.py`.
