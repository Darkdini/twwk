# TWWK · red-team PoC («версия врага»)

Контролируемый набор для **авторизованного** тестирования своего же сервера
«Третий мир: Война Королей». Цель — доказать или опровергнуть находки из
анализа клиента, в первую очередь:

> **№1 — открытый канал.** Игра ходит сырым TCP без TLS → трафик читается и правится.
> **№2 — доверие к клиенту.** Нет nonce/счётчика/MAC → кадры можно повторять и подделывать.

## ⚠ Границы (важно)

- Запускать **только против сервера и аккаунта, которыми ты владеешь** (свой тест-шард / локальная копия).
- **Не** направлять на боевой сервер с живыми игроками.
- Это диагностический PoC для починки серверной валидации, а не средство игры против других.

## Почему именно прокси, а не «поддельный клиент»

Тело сообщений TWWK сериализуется **кастомными обфусцированными классами**
(`i.g`, `w.d`, `k.e`…), а дамп `twwk_msg` — это уже разобранные события, не байты
с провода. Синтезировать клиент с нуля = угадывать сериализатор. Поэтому «врагом»
здесь выступает **прозрачный MITM-прокси**: он берёт *настоящие* валидные кадры
твоего клиента и повторяет/мутирует именно их. Так сделал бы атакующий в одной
сети с тобой — и так проверяется серверная защита без реверса формата.

## Состав

| Файл | Что делает |
|---|---|
| `proxy.py` | MITM-прокси: `клиент → прокси → твой сервер`. Пишет все кадры в `captures/`, умеет подменять байты на лету (`--tamper`). |
| `replay.py` | Повторяет записанную сессию на сервер. Тест анти-replay (находка №2). |
| `captures/` | Записи сессий (`session_N.jsonl`, `dir`=c2s/s2c, `hex`). |

## Как пользоваться

**1. Узнать адрес сервера.** Клиент берёт его из `raw/crow_ser`; подставь свой тест-сервер.

**2. Поднять прокси** (впиши свой `--target-host/--target-port`):
```bash
python3 redteam/proxy.py --target-host 127.0.0.1 --target-port 9933 --listen-port 9933
```

**3. Завернуть клиент на прокси.** На устройстве/эмуляторе направь `твой-домен`
на IP машины с прокси (файл `hosts`, локальный DNS или тестовый билд с адресом прокси).
Поиграй: построй здание, собери ресурс, отправь атаку — прокси всё запишет и разберёт.

**4. Повторить действие (находка №2).** Найди в выводе номер кадра нужного действия и:
```bash
python3 redteam/replay.py captures/session_1.jsonl \
    --host 127.0.0.1 --port 9933 --only-frame 42 --repeat 5 --read-replies
```
Затем посмотри в игре:
- действие применилось ещё раз (лишние ресурсы/команды) → **сервер доверяет клиенту, анти-replay нет → УЯЗВИМО**;
- сервер отверг повтор / разорвал сессию → **защита есть, ок**.

**5. Подделка на лету (находки №1+№2).** Найди в hex-дампе значение (напр. количество)
и подмени при пересылке:
```bash
python3 redteam/proxy.py --target-host 127.0.0.1 --target-port 9933 \
    --tamper c2s:00000001:000003e7
```
Если сервер принял изменённый кадр — он верит клиенту по содержимому.

## Как читать результат

| Наблюдение | Вывод | Что чинить |
|---|---|---|
| Кадры видны в открытом виде | нет TLS (№1) | TLS + cert pinning |
| Повтор кадра применился | нет анти-replay (№2) | session-token + sequence + MAC |
| Подмена байт сработала | сервер верит содержимому | серверная авторитетная валидация |
| Повтор/подмена отвергнуты | защита работает | — |

Связка «прокси записал → replay повторил → подмена прошла» — это полное
практическое подтверждение того, что в отчёте было статикой.
